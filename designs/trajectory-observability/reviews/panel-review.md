# Expert review and resolutions

All six lenses found the architecture viable. The following requirements are incorporated before installation.

- Security/Operations: private immutable event files and directories; symlink rejection; exclusive temporaries. HTTPS or loopback HTTP collector URLs, no redirects or URL credentials, bounded replies, sanitized errors. Default exports hash identities and omit task/repository/actor text. Content export is explicitly potentially sensitive. Installer switches the current pointer only after verifying a complete manifest. Post-rename errors include sequence and batch ID.
- Reliability/Data: validate full batches before replay, including revision preconditions, unique batch/attempt IDs, start/result correspondence, and applied-result revision. Verification start is observation-only, so it does not alter the captured task revision. It imports legacy baselines before executing any command. HEAD and record revision are checked; as in the existing release, concurrent uncommitted source changes are outside the guarantee and are tested/documented. Imported blocked durations are lower bounds from observation time, with unknown earlier duration. Clock reversals are explicit anomalies. Individual command duration uses monotonic time.
- Developer Experience/Scalability: reports use a stable sequence/index cursor, explicit limits and coverage. Export bodies are capped at 8 MiB and fail with narrower-filter guidance; no silent truncation. Rendering and HTTP happen after releasing the state lock. Prototype budgets: 1,000 batches under 2 seconds to replay, 10,000 under 15 seconds, and report peak memory under 128 MiB on the measured local machine; these are acceptance targets, not established baselines. Capture concurrent writer latency during reporting. Fail the build or optimize if budgets are exceeded. No durable cache shortcut is assumed safe.
- Integration: `agent_checkpoint.integration` is the supported downstream adapter surface. A stdlib installer verifies all package files against a SHA-256 manifest before switching a private pointer. Dotfiles owns only policy, the upstream commit pin, and adapter loading. Future features/fixes are made upstream. Migration backs up state, installs upstream, updates all entry points and hook runtime, and tests them before first history mutation. Old, already-running hook code cannot be fenced by the old file format: restart existing agent sessions; rollback after migration means reinstall a compatible upstream version, never resume legacy writers. Migration receipts preserve imported record hashes.

The user approved the storage constraints and explicitly requested plan, build and downstream migration. No additional design permission gate is needed. Merge approval remains separate.

## Implementation follow-up

Security/Operations confirmed directory-parent durability, runtime publication flushes, legacy import sanitization with raw source fingerprints, and export-boundary redaction. Installer preparation failure preserves the prior selector. Reliability/Data confirmed coverage uses complete history for selected tasks, filtered counters remain separate, and export uses one replay snapshot. No remaining major blockers were reported. The local HTTP receiver runs in the full suite with socket permission; the sandboxed reviewer could not bind it.
